# 输入热路径优化实施记录

用户已确认实施本轮六项性能优化。修改遵守 TSF 线程亲和性、密码输入旁路、进程内共享资源和跨进程原子保存约束。

## 实施计划

1. 统计使用进程内共享后台写入器，前台只累计字符数量；后台合并增量，保留命名互斥和原子替换。明确跨天、保存失败和 DLL 卸载前的收尾行为。
2. 混拼搜索用可回溯节点保存路径，候选输出时再组装字符串和学习词段；剪枝使用有界选择，减少完整对象复制。
3. 查询引入确定性的整体工作预算和分阶段计数，保留精确候选，约束昂贵搜索；比较候选质量与延迟。
4. 首次获取一页及少量探测候选，翻页、展开或跨越已加载边界时扩展，保持已显示候选顺序以及置顶、英文、自定义短语规则。
5. 配置在同一按键或绘制调用内复用，结合短周期检查与主动通知保持更新；置顶配置减少重复文件属性访问。
6. 剪贴板通知、读取、图片处理和入库转移至独立 STA 线程，通过界面 Dispatcher 发布完成事件；使用合成文本与图片验证界面线程可响应。

## 基准约定

优化前证据位于 `artifacts/audit-20260906/`。本机为 Windows 11、Intel i5-4460；比较统一使用 Release、相同词库与回退模型，分别测量首屏查询、多页查询和统计入队。统计及剪贴板测试使用隔离目录。交互宿主验证与纯引擎测量分别记录，不把纯查询时间当作完整按键延迟。

## 阶段验证

统计、配置、置顶、输入策略、引擎功能、英文排序、候选窗口的七项回归已通过。设置程序构建为零警告、零错误，设置逻辑测试通过。最终合成剪贴板测试中，1920×1080 原生 PNG 的读取与保存为 61.27 ms，位图采集包含 PNG 编码为 104.82 ms；长文本、图片像素及入库结果均验证完整，界面 Dispatcher 仍能响应。

48 组输入的前九项共 418 个候选位置，初版优化的多页结果与基线一致。缩小首屏结果数后，保留短前缀竞争池和固定的混拼排序配额，首屏的 418 个位置也与基线一致。原始对比保存在 `quality-baseline.tsv`、`quality-current-10.tsv`。

进一步优化前缀候选构造与混拼去重后，首屏的 418 个候选文本、拼音、覆盖长度、来源与分段信息均与基线一致。最终基准保存在 `optimized-final-10.tsv` 和 `optimized-final-90.tsv`。

正式入口 `scripts/build.ps1 -Config Release -NoPackage` 已通过：x64 的 28 项非交互 CTest、x86 的 4 项正式子集均通过，WPF 自包含发布成功。收尾调整确保展开态继续输入时仍获取五行数据，随后 x64/x86 各 8 项相关回归和最新设置逻辑测试全部通过。完整日志分别位于 `formal-build.log`、`final-targeted-x64.log`、`final-targeted-x86.log` 和 `final-settings-logic.log`。

手动重测命令：

```powershell
build-release\query_benchmark.exe <词库目录> <隔离用户目录> 10
build-release\query_benchmark.exe <词库目录> <隔离用户目录> 90
```

合成剪贴板测试不会修改系统剪贴板；实际第三方程序的延迟提供、长期占用和大型图片
仍需真实宿主验证。性能数字不包含 TSF 编辑会话和候选绘制，也不是所有设备的延迟保证。

统计采用 150 ms 合并窗口。正常 DLL 卸载前会在 Loader Lock 外完成保存；宿主强制
终止或没有执行卸载收尾时，尚未保存的最后一小批统计可能丢失。线程创建或保存失败
不会回退到 TSF 线程同步写盘。
