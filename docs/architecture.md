# 架构与运行时行为

本文描述当前源码。平台、编译标准和目标定义以 [CMakeLists.txt](../CMakeLists.txt) 为准：
Windows 10/11 x64、C++17、x64 与 WOW64 x86 TSF DLL，以及 .NET 8 WPF 设置中心。
历史发行范围见 [CHANGELOG](../CHANGELOG.md) 和 [v2.0.2 说明](releases/v2.0.2.md)。

## 模块与职责

| 模块 | 职责与主要入口 |
|---|---|
| [TSF 接入层](../src/ime/text_service.cpp) | `TextService` 管理激活、焦点、按键、候选与上屏 |
| [编辑会话](../src/ime/edit_sessions.cpp) | `SetCompositionEditSession`、`InsertTextEditSession`、`EndCompositionEditSession` 和已有文本接管 |
| [候选窗口](../src/ime/ui/candidate_window.cpp) | 无焦点分层窗口、DirectWrite 文字、GDI+ 皮肤/背景、命中测试与导航 |
| [共享界面](../src/ime/ui/shared_status_ui.cpp) | 每个 TSF UI 线程的生命周期窗口、软键盘和当前服务绑定 |
| [拼音引擎](../src/engine/pinyin_engine.cpp) | 全拼/小鹤双拼、简拼、纠错、混拼、候选融合与学习 |
| [词典索引](../src/engine/dictionary.h) | 字符 Trie、音节 Trie、键索引和用户词元数据 |
| [共享引擎](../src/engine/shared_engine.cpp) | 每个宿主进程共享加载、就绪等待与卸载收尾 |
| [配置与权限](../src/common) | 配置快照、日志、DACL、用户数据路径和统计 |
| [设置中心](../settings) | WPF 页面、记录数据库、后台监听、直接上屏及粘贴辅助 |

TSF 接口层调用引擎取得候选，UI 只呈现候选和发送操作回调。普通拼音索引与
Grammar 文件中的 Darts 双数组是不同的数据结构；本项目不链接 librime。

COM 标识在双架构中一致：

- CLSID：`{7C4E9F2A-1B3D-4A8E-9F6C-2D5E8B1A4C7F}`。
- Language Profile：`{3A8B5C2E-9D1F-4E6A-B7C8-5D2E9F1A3B6C}`。
- LangID：`0x0804`。

Windows 根据宿主位数选择对应 COM 注册视图。两份 DLL 使用静态 CRT，
设置中心的正式发布包含自己的 .NET 8 桌面运行时。

## 拼音查询与排序

当前输入方案只有全拼和小鹤双拼。输入先规范化或解码，然后结合精确拼音、前缀、
简拼、带权模糊纠错及混拼词图取得候选；中英混输、置顶和自定义短语在相应阶段参与融合。
不能把整体查询概括为单一的四级查表顺序。

- 词典提供字符 Trie 与音节 Trie；混拼支持完整音节和声母交错。
- 束搜索使用有界路径和词边，混拼输入最多处理 48 个字母；
  主要混拼路径保留宽度为 64，每位置的词边读取有界。
- `QueryOptions::max_work_units` 默认 300,000，单次配置限制在 1,000,000 以内。
  索引访问、纠错和词图展开共同消耗工作预算。
- 排序综合匹配质量、词频、学习、短词先验和语言模型；不能用一个旧的
  `match_cost - learning_score` 公式描述全部排序。
- 语言模型依次尝试 `rime-moqi-zh.gram`、`system_ngram.bin`、兼容旧安装的
  `zh-moqi.gram`。`system_lexeme_prior.bin` 提供独立的单字、双字常用度先验。
- 普通候选先取一页及一个探测项，翻页或展开时继续加载，最多保留十页。
  追加时保持已显示候选的位置，展开窗口最多显示五行。
- 预算耗尽时保留已有结果，必要时生成不可学习的原始输入候选。

用户学习保存在独立覆盖层，基础词库与英文索引不因学习整份复制。
`PredictNext` 和相关配置仍存在，但 `TextService::ShowAssociation` 当前隐藏上屏后的
独立联想候选窗，用户搭配主要参与后续查询排序。

## 冷加载与缓存

`PinyinEngine::Initialize` 优先采用 EngineSnapshot v2。快照包含排序词条、键索引、
字符/音节 Trie、音节表、指纹和英文词典，通过偏移量布局映射为只读数据；
语言模型单独加载，不放入引擎快照。

快照缺失、源文件身份变化或结构校验失败时，回退到文本及 `*.txt.bin` 派生缓存。
传统装载完成并发布引擎后，再尝试保存新快照。快照生成失败不应妨碍输入；
加载失败时保留此前可用的引擎状态。缓存格式、清单边界和来源核验见[词库治理](lexicon-governance.md)。

引擎未就绪时，输入线程通过 `SharedEngine::WaitForReady` 最多等待 300 ms。
超过上限且仍在加载时，保留组合并通过候选窗定时器等待，暂不把原始拼音作为选词结果。
轮询同时核对输入世代、上下文和敏感范围；焦点切换或取消会使旧回调失效。
空格、数字及鼠标选择会在引擎刚就绪时补查候选。

`v/vv` 记录与短语列表不依赖主词库就绪。快照和完整统计模型使用只读映射，
传统词库回退装载仍可能构造堆内存索引，不能宣称所有加载路径都零拷贝。
性能数字和复测方法见[性能说明](performance-optimization.md)。

## TSF 组合与首键恢复

- 创建组合与写入预编辑在合法编辑会话中完成。
- 上屏优先原位替换当前组合范围，再清除显示属性并结束组合，避免留下原始拼音。
- 最终文字已经写入但组合结束失败时，只排队清理旧组合，不重复插入正文。
- 组合结束通知按 COM 对象身份核对；旧通知不能释放当前新组合。
- 延后清理持有独立的旧对象，只在预编辑正文仍匹配时删除它。
- 复制或粘贴后，宿主可能先写入首字母。恢复过程核对上下文、范围、文字、选区和输入世代，
  分阶段结束宿主旧组合并创建唯一的新组合；取消或焦点切换后不在旧位置补写。
- 新建组合被宿主延后结束时，当前代码按组合年龄、恢复计数、上下文和取消状态判断，
  可在下一消息轮次重建；主动取消不能触发重建。
- 候选窗受控重建 HWND 时保留排队动作与逻辑定时器；真正销毁时取消它们。

窗口与 TSF 对象只在所属 UI 线程操作。`DllMain` 不等待线程，也不销毁窗口。
具体状态、故障原因和回归入口见[组合生命周期](composition-lifecycle.md)。

## 候选窗、定位与按键

候选窗不激活宿主外的输入焦点。普通候选支持选中、置顶、分页和展开；
`v/vv` 使用最多十条可见记录的竖向列表，附带搜索入口和滚动条。
自定义皮肤可提供背景、挂件及动画，因此不能把全部皮肤描述为固定尺寸的纯色圆角框。

候选位置优先使用已确认的组合末端。首次布局未就绪时保留隐藏状态，按布局世代有界重试。
合法的同步只读编辑会话用于取得 `GetTextExt`；特殊终端和缺少可靠 TSF 几何信息的宿主
使用经过校验的系统光标或宿主窗口回退。当前实现不将
`GetTextExt(TF_INVALID_COOKIE)` 作为通用定位步骤。
开始菜单等宿主缺少后续布局通知时使用较长防抖，避免永久隐藏或跳回旧位置。

普通组合中，空格提交当前选择，Enter 和单独 Shift 提交原始输入；
`v/vv` 的 Enter 提交选中记录，`vvv` 的 Enter 提交计算结果。
数字键在工具模式中有专门的筛选或表达式语义。完整按键表见
[README](../README.md#常用按键)和[输入策略](privacy-input-policy.md)。

旧“中 / 全 / 键 / 设”悬浮状态栏保持隐藏，`F9` 切换软键盘，
`F10` 切换全拼与小鹤双拼，候选窗右键打开设置中心。

## 设置中心与复制记录

设置中心有七个页面：常规设置、输入方案、自定义短语、剪贴板、外观与皮肤、
词库与隐私、帮助说明。`VModeOpenWindow` 和 `VvModeOpenWindow` 决定是否直接打开
独立记录/短语窗口，默认关闭。

单实例隐藏设置进程承接系统剪贴板通知。独立 STA 工作线程处理 OLE 读取、图片编码、
散列及 SQLite 入库；通知合并约 50 ms，再通过界面 Dispatcher 发布结果。
记录类型为文本、图片和文件路径，不保存 HTML/RTF 富文本。

数据库使用 SQLite WAL 和事务，查询结合时间索引与 FTS5 trigram；
短查询使用普通检索。图片保存在受管 `images/` 目录，数据库保存元数据和路径。
旧 `history.json` 在迁移锁内首次导入，成功后保留 `history.json.migrated.bak`；
损坏 JSON 不被覆盖。

### 删除与选择

原生列表和独立窗口都支持上下键及 Delete。删除后保留窗口与搜索条件，
选择原位置补位的下一条，删除末条时选择上一条，清空后仍显示空列表。
原生窗口在鼠标抬起时确认删除或选词，完整手势互斥；
按下与抬起之间候选变化或鼠标捕获丢失时取消操作。
文本记录也携带稳定 ID，删除不依赖标题或正文相等。

独立窗口通过单独的按钮处理提交和删除，异步删除前截断事件路由，
持久化成功后刷新并恢复列表焦点。搜索框中的 Delete 继续编辑搜索文字。
窗口关闭期间的失去焦点通知不能再次调用 Close。

### 三种上屏路径

| 路径 | 行为 |
|---|---|
| 原生列表的短单行文本 | 通过当前 TSF 编辑会话直接提交 |
| 原生列表的图片、多行或超长文本 | 使用记录 ID 或一次性文本请求启动辅助粘贴 |
| 有有效会话的独立窗口文本 | 用一次性令牌交回原 TSF 上下文，支持多行与长文本，无需改写系统剪贴板 |

直接上屏协议位于 [原生请求模块](../src/ime/direct_text_commit_request.cpp) 和
[设置侧请求存储](../settings/DirectTextCommitRequestStore.cs)。
128 位令牌标识会话，UTF-8 正文上限为 16 MiB，临时文件原子发布。
宿主在原窗口恢复前台、上下文仍匹配且不是敏感输入范围时消费请求；
设置程序等待确认，取消或超时会清理未消费的请求。
上下文改变、敏感输入或失败不会自动转成系统粘贴。

没有直接会话的文本回退使用 [ClipboardTextWriter](../settings/ClipboardTextWriter.cs)，
在后台即时写入 `CF_UNICODETEXT` 和内部粘贴标记，打开剪贴板阶段最多重试约一秒。
图片使用后台 STA 写入 PNG 与 Bitmap，正常半透明保持原样，
只有检测到全部 Alpha 为零且存在颜色内容时才修复不透明度。
发送粘贴前再次核对前台和剪贴板序号，避免激活期间的新复制被误用。
等待准备期间独立窗口保持可见，Esc 可取消尚未提交的操作。

## 数据、共享资源与验证入口

系统词库由 `%ProgramData%\CaishenPinyin\data\lexicon\current` 选择；
个人设置、学习、短语、置顶、统计、记录和请求文件位于
`%LOCALAPPDATA%\CaishenPinyin\`。AppContainer 的 DLL 不直接访问个人数据；
公共资源和系统快照允许按权限只读使用。

每个进程共享引擎、模型和统计写入器；共享界面按 TSF UI 线程管理。
统计前台只累计日期和字符数量，后台合并约 150 ms 内的增量并原子保存。
配置与置顶通常每 100 ms 检查文件变化，主动通知可立即刷新；
`RuntimeConfigScope` 让同一轮按键或绘制复用配置快照。

对应回归由 [CMakeLists.txt](../CMakeLists.txt) 注册。重点包括 `input_policy`、
`composition_lifecycle`、`candidate_window`、`clipboard_helper`、
`direct_text_commit_request`、`engine_snapshot`、`learning_persistence`、
`settings_logic` 和 `settings_ui_smoke`。
自动化测试不能代替每个 Windows 宿主的实际兼容性验证。
