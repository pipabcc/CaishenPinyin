# TSF 组合生命周期与首键恢复

主要实现为 [TextService](../src/ime/text_service.cpp)、
[编辑会话](../src/ime/edit_sessions.cpp)和
[候选窗线程调度](../src/ime/ui/candidate_window.cpp)。
本文描述当前行为与回归约束，输入隐私见[输入策略](privacy-input-policy.md)。

## 组合的基本约束

组合范围属于宿主的 TSF 上下文，修改正文必须持有合法编辑会话。
输入法内部状态、宿主活动组合和候选窗必须保持一致：

- `SetCompositionEditSession` 按需创建组合并写入预编辑。
- `InsertTextEditSession` 优先原位替换当前组合，调整光标、清理显示属性后结束组合。
- 最终文本已写入但结束失败时，后续只清理旧组合，不重新插入或删除已提交文字。
- `OnCompositionTerminated` 比较 COM 的 `IUnknown` 身份，迟到的旧通知不释放当前新组合。
- 需要异步结束时，清理会话独立持有旧组合，不通过成员指针触碰稍后的新组合。
- 清理前核对最近一次写入的预编辑；宿主已修改的正文保留，敏感范围不读取或改写。

组合显示属性和范围收尾都要验证。仅检查最终文字或强制改变候选窗颜色，
无法发现宿主仍保留的活动组合及局部高亮。

## 复制或粘贴后的首键

某些宿主在复制、粘贴或焦点切换后，可能先自行写入首字母，未按通常路径派发给输入法。
首键恢复只处理经过校验的短范围，不能扫描并重插任意历史正文。

`AdoptExistingTextEditSession` 核对上下文、输入世代、文字、选区和范围。
若有一个完全位于目标范围内的宿主组合，先结束它，再确认目标仍未变化，
随后创建唯一的新组合并设置完整显示属性。多个重叠组合、范围越界或回调修改目标时停止接管。

[ITfContextComposition::TakeOwnership](https://learn.microsoft.com/en-us/windows/win32/api/msctf/nf-msctf-itfcontextcomposition-takeownership)
没有可用的实现，不能用它代替交接，也不能通过“结束所有组合”绕开范围校验。

宿主与输入法可能使用不同的编辑客户端和写锁。结束宿主组合、新建输入法组合分阶段
投递到原 TSF 线程。`TF_ES_ASYNC` 只协调编辑锁，不保证宿主当前消息中的延后收尾已经执行；
因此还需要所有者线程消息队列作为阶段边界。

等待交接时缓存后续字母和空格操作。焦点改变、取消、选区移动或正文变化会使旧任务失效，
不能在已经过时的位置补写。

## 新组合被宿主延后结束

当前 `OnCompositionTerminated` 还包含受条件限制的重建路径。
当结束通知确实对应当前组合时，满足以下条件才安排恢复：

- 不是输入法主动提交或取消。
- 仍有待输入拼音，当前编辑上下文有效且仍为顶层上下文。
- 不处于敏感输入范围或英文模式。
- 组合创建距当前不超过 1500 ms，且当前恢复计数小于 2。

恢复通过 `PostOwnerThreadAction` 在下一消息轮次执行。
`RecreateCompositionAfterUnexpectedTermination` 再次验证上下文和状态；
期间已有新活动组合时不重复创建，失败或条件变化时取消恢复并清理界面。
主动 Esc 不能被当成宿主意外终止而重新恢复。

这一分支与已有首字母的接管是不同阶段。修改时需要分别验证创建、意外结束、
再次输入和主动取消，不能只保证候选窗重新出现。

## 候选窗重建与任务生命周期

候选窗首次绑定宿主或切换所有者时可能重建 HWND。
受控重建保留排队动作、轮询回调及剩余延迟，并向新窗口重新投递；
真正销毁窗口或结束服务时取消任务。

原生记录列表还维护按下时的候选与内容代次。列表变化、隐藏或丢失鼠标捕获后，
旧抬起事件不能提交补位记录。删除和选择在抬起时分别处理，
不能把删除后的刷新解释为一次新的点击。

## 回归入口

| 测试 | 主要覆盖 |
|---|---|
| `composition_lifecycle` | 旧通知、只读会话切换、延后清理、正文被改写、提交后结束失败、首键交接及意外终止恢复 |
| `tsf_e2e_core` | 真实 TSF 编辑、活动组合、选区和显示属性清理 |
| `candidate_window` | 所有者重建、排队任务与定时器、点击身份、删除互斥和滚动 |
| `firstkey_recovery*` | 复制、连续快打、清扫恢复、键盘粘贴和鼠标粘贴五种入口 |
| `settings_ui_smoke` | 独立窗口事件路由、关闭重入、直接上屏请求和剪贴板等待取消 |

```powershell
ctest --test-dir build-release -C Release -R "composition_lifecycle|tsf_e2e_core|candidate_window" --output-on-failure
ctest --test-dir build-release -C Release -R firstkey_recovery -V
```

核心用例使用 Windows 提供的 TSF 文档、范围和 COM 对象，并以受控通知复现交错。
`TF_TMAE_NOACTIVATETIP` 隔离机器上已安装的输入法；
首键集成测试仍需要交互桌面，不能在无桌面 CI 中当作已验证。

测试使用合成正文与隔离数据。部分用例短暂占用系统剪贴板以验证直接提交或取消，
不覆盖用户剪贴板内容；原生剪贴板写入测试另用隔离窗口站。
这些验证不能替代每个软件和网页编辑器的实际兼容性验收。

## 开发诊断

CMake 选项 `SHURU_INPUT_LIFECYCLE_TRACE` 默认关闭。
启用后记录事件、进程/线程、对象标识、状态和错误码，
不记录字母、输入正文、候选或剪贴板内容。

诊断构建只用于排查明确问题，完成后恢复关闭。
重新构建并注册不等于旧宿主已重载，实际验证需按[重载说明](installer.md#升级后的重载与排查)
退出相关应用后进行。
